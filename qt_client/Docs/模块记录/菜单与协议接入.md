# 模块记录：弹出菜单、输入弹窗与协议接入

这一批把“界面已经有入口、但请求没发”的协议接上了，并加了三个弹出菜单。

## 类关系

```
MainWindow
 ├─ ToolRail
 │    ├─ QPushButton #railAddButton（“＋”，跟在最后一个社区图标下面）→ QMenu：创建社区 / 创建群聊 / 申请加入社区 / 申请加入群聊 / 添加好友
 │    └─ 社区图标右键 → QMenu：邀请至社区 / 创建频道 / 离开社区
 ├─ HomePage “待定”页：好友申请行（忽略 / 接受）
 ├─ ChatPage
 │    ├─ MessageRow × N（一条消息一个，右键发 menuRequested）→ QMenu：回复 / 复制文字 / 撤回
 │    └─ Composer：#composerReply 回复提示条（正在回复 @某人 ×）
 └─ InputDialog（QDialog）：标题 + 若干输入框 + 取消 / 确定；没有输入框时是确认框
```

`menus::prepare(QMenu*)`（`ui/MenuStyle.h`）：三个菜单共用，设 objectName `appMenu` + 去系统边框阴影 + 背景透明（圆角外不发黑）。

## 协议对照（请求 → 字段 → 入口）

| type | 字段 | 入口 |
|---|---|---|
| `private_chat` / `group_chat` | 多带 `reply_to_message_id` | 消息右键“回复”后发送 |
| `delete_message` | `message_id` | 消息右键“撤回”（只有自己的消息有） |
| `show_friend_requests` | — | 登录成功、好友相关通知之后 |
| `accept_friend` / `reject_friend` | `sender_UID` | “待定”页 接受 / 忽略 |
| `add_friend` | `email`、`apply_message` | “＋”→ 添加好友 |
| `create_group` | `group_name` | “＋”→ 创建群聊；主页“＋ 新建群聊” |
| `send_join_group` | `group_UID` | “＋”→ 申请加入群聊 |
| `create_community` | `group_name`、`description` | “＋”→ 创建社区 |
| `join_community` | `community_id`、`apply_message` | “＋”→ 申请加入社区 |
| `community_add_member` | `community_id`、`target_user_UID` | 社区右键 → 邀请至社区 |
| `create_channel` | `community_id`、`group_name`、`category`（空则“一般”） | 社区右键 → 创建频道 |
| `leave_community` | `community_id` | 社区右键 → 离开社区（先弹确认） |

收到的：

| type / 文本 | 处理 |
|---|---|
| `delete_message`（推送） | `ChatPage::removeMessage`：把那一行拿掉 |
| system `Message [N] deleted` | 同上（自己撤回成功） |
| system 发送失败（not your friend / does not exist…） | 拿掉最早那条灰色乐观消息，原因显示在状态栏 |
| system `[昵称] (UID): 留言` 多行 / `No pending friend requests` | `MainWindow::handleFriendRequestList` 解析成 `QList<FriendRequest>` → `HomePage::setFriendRequests` |
| system 含 Group created / Community created / You are now friends with… | `MainWindow::refreshAfter`：200ms 后重新拉通讯录 / 社区 / 好友申请 |

## 调用流程

```
右键消息 → MessageRow::contextMenuEvent → emit menuRequested（排队连接）
        → ChatPage::showMessageMenu：
            回复     → m_replyTo = 这条消息；Composer::setReplyTarget 显示提示条
            复制文字 → 剪贴板
            撤回     → 发 delete_message → 收到 "Message [N] deleted" → removeMessage

点“＋”里某项 → ToolRail::addActionTriggered(AddAction)
            → MainWindow::handleAddAction：ask() 弹 InputDialog → 组 Envelope → ChatClient::send
            ← system 文本：状态栏显示结果；refreshAfter 看关键字决定重新拉哪个列表
```

## 核心逻辑说明

- **服务端没有结构化的结果回复**：创建 / 加入 / 邀请这些请求的成功失败都是一句英文 system 文本，
  所以结果只显示在状态栏，列表刷新靠匹配关键字（关键字和 web 端 `backendClient.js` 的 `systemMessage` 保持一致）。
- **菜单不在被点控件自己的事件处理里弹**：菜单 `exec` 期间还在收消息，被右键的那一行 / 那个社区图标可能被删掉。
  消息菜单用排队连接 + `QPointer`，社区菜单用 `QTimer::singleShot(0)`，弹的时候栈上已经没有那个控件了。
- **乐观消息按发送顺序确认**：`m_pendingIds` 是先进先出的临时 id 队列，`m_rows` 是 id → 行；确认时把行从临时 id 挪到真实 id 下。
  没确认的消息没有真实 id，菜单里“回复”“撤回”是灰的。
- **换 objectName 要重新套 QSS**：`MessageRow::confirm` 里 `unpolish` + `polish`，灰色才会变回正常颜色。
- **InputDialog 不新增样式**：卡片 / 标题 / 输入框 / 按钮分别复用 `#noticeCard` `#noticeText` `#settingsInput` `#settingsRowButton` `#primaryButton`。

## 后续补充：邀请好友、入群审批、文件封面

- **邀请好友改成从好友列表点**（web 端是手动输 UID）：`InviteDialog` 列出好友，每行一个“邀请”按钮，点过变成“已邀请”。
  入口：通讯录右键群聊 →“邀请好友”（`group_add_client {group_UID, target_user_UID}`）；
  社区右键 →“邀请至社区”也换成了同一个弹窗（`community_add_member`）。请求由 `MainWindow::inviteFriends` 发。
- **入群 / 入社区申请审批**：“待定”页拆成独立的 `PendingPage`，三节：好友申请 / 群聊申请 / 社区申请。
  - 拉取：收到通讯录后对每个群发 `show_group_requests {group_UID}`；收到社区列表后对自己是 owner 的社区发 `show_community_requests {community_id}`。
  - 回复是文本（首行带 `for group [id]` / `for community [id]`，其后每行 `Requester UID: N, Message: 留言`），`MainWindow::handleJoinRequestList` 解析。
    不是群主的群会回一句不带 id 的失败，直接吞掉不显示。
  - 审批：`handle_join_request {group_UID, requester_UID, accept}` / `handle_community_join_request {community_id, requester_UID, accept}`；
    服务端回 `Join request accepted / rejected` 后重新拉一遍申请列表。
  - 这部分代码在 `MainWindowRequests.cpp`（还是 `MainWindow` 类，分文件只是为了不超 400 行）。
- **文件封面等附件外观集中在 `ui/FileCover.h/.cpp`**（`filecover::` 一组纯函数）：
  `cover(文件名, 边长)` 各格式封面、`imagePlaceholder(尺寸)` 图片默认背景图、`videoCover(尺寸)` 视频封面、
  `isImage` / `isVideo` / `label` / `formatSize`。分类表和配色抄自 web 端 `file-cover.js` 与 `reference-theme.css`，改那边要同步。
  `MessageRow::buildAttachment` 用它显示文件消息（`Message` 多了 `isFile / fileId / fileName / fileSize`）。
  封面是画出来的图，所以分类配色表在代码里，不在 QSS。

## 明确不做

- **表情反应**（快捷反应、添加反应、查看反应）：客户端明确不做，不是“还没做”。

## 已知未做（web 端有，这边还没有）

- 消息菜单：下载附件、复制消息链接。web 端的转发 / 标记未读 / 举报本身就是“未开发”，没放。
- 文件消息只显示封面 / 占位图，下载、图片真实预览、发送文件都没接（`file_*` 协议）。
- 社区菜单：“社区设置”（web 端是一整个设置页）。
- 通讯录右键只有群聊的“邀请好友”；删除好友 `remove_friend`、设置备注 `set_friend_remark`、退群、改群名等没做。
- 社区页本身（频道列表 `show_community_channels`、成员 `show_community_members`、频道聊天 `channel_chat`）没做，所以创建频道之后在这边还看不到。
- 文件 / 头像相关协议（`file_*`、`set_avatar`）、`verify_email`、`change_theme` 没接。
- 菜单里“离开社区”没有做成红色（QMenu 的 QSS 不能单独给某一项上色）。
