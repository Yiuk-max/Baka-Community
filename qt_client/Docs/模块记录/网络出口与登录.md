# 模块记录：网络出口与登录（ChatClient）

## 类关系

```
main.cpp
 ├─ ChatClient（主线程，QObject）──── 唯一的网络出口
 │    ├─ QThread  m_netThread
 │    │    └─ WsCore（工作线程）── QWebSocket，只搬 QByteArray
 │    ├─ PacketCodec（Envelope <-> 4B 长度 + protobuf）
 │    ├─ QTimer 心跳（30s）
 │    └─ QTimer 认证超时（10s）
 ├─ LoginDialog ── LoginPage（表单 + 输入校验）
 └─ MainWindow（只订阅 ChatClient 的信号）
```

页面不 include `WsCore.h`，只和 `ChatClient` 的信号/槽打交道。

## 关键 API（`src/net/ChatClient.h`）

| 成员 | 说明 |
|---|---|
| `start()` | 起网络线程并连接服务器 |
| `send(Envelope)` | 编码后投递到网络线程发送，后续所有业务请求都走它 |
| `login(identity, password)` | 纯数字按 `UID` 登录，否则按 `email` 登录 |
| `registerAccount(nickname, email, password)` | 注册；成功后**不**建立登录态 |
| `uid()` / `username()` / `isConnected()` | 当前账号与连接状态 |
| 信号 `authStarted` / `loginSucceeded` / `registerSucceeded(uid, email)` / `authFailed(msg)` | 认证过程 |
| 信号 `connected` / `disconnected(reason)` / `statusMessage` / `heartbeatAcked` | 连接状态 |
| 信号 `envelopeReceived(Envelope)` | 心跳、认证之外的所有消息，留给页面分发 |

## 调用流程

```
启动   main → ChatClient::start() → WsCore 连接
连上   onConnected → 心跳 → QSettings 有 token ? verify_token : 等用户操作
登录   LoginPage::loginRequested → LoginDialog 转发 → ChatClient::login
         → authStarted（按钮变“请稍候…”）→ 发 login
         ← login_success → 存 token → loginSucceeded → LoginDialog::accept → 显示 MainWindow
         ← system 文本   → authFailed(中文提示) → LoginPage::showError
注册   ChatClient::registerAccount → 发 register
         ← "Registration successful ... UID n or email." → registerSucceeded
         → LoginPage 切回登录表单并填好 UID，用户输入密码登录
超时   10s 没有回应 → authFailed("服务器响应超时，请重试")
```

## 核心逻辑说明

- **认证结果靠“在途状态”判断**：后端没有错误码，登录/注册失败只回 `system` 文本。
  未登录时服务端不会主动推送，所以 `m_pending != None` 期间收到的 `system` 就是本次请求的结果
  （`ChatClient::handleFrame` → `handleAuthReply`）。
- **token**：存在 `QSettings` 的 `auth/token`（Windows 下是注册表
  `HKCU\Software\Baka Community\Baka Community`）。`verify_token` 失败就删除本地 token。
- **主窗口先创建后显示**：`login_success` 之后服务端会紧跟着推好友申请和离线消息，
  所以 `MainWindow` 在 `client.start()` 之前就建好并订阅 `envelopeReceived`，登录成功后才 `show()`。
