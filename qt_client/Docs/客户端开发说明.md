# 客户端开发说明（WebSocket + protobuf + Widgets）

> 编码前先读 [`开发约束.md`](开发约束.md)：C++17、纯 C++ 建 UI + 布局管理器、不用 `.ui`、
> 每个页面独立 `QWidget` 子类、QSS 只做视觉、Signal/Slot 通信、禁止巨型类/文件。

本文是 Qt 客户端要实现的协议与架构约定。**字段号以 `proto/message.proto` 为准**，
系统提示文本、错误语义以 `../-----server/Docs/客户端接口文档.txt` 和后端源码为准。

## 1. 连接与帧格式

```
wss://bakacomm.world/ws          ← 生产环境（Cloudflare 终止 TLS；ws:// 直接 301 到 https）
```

- 握手路径必须是 `/ws`；错误路径 404，非 Upgrade 请求 426。
- 业务消息一律 **binary 帧**，帧 payload 结构：

```
┌───────────────────────┬──────────────────────────┬─────────────────┐
│ 4 字节 payload_len     │ protobuf Envelope 字节    │ file_data(可选)  │
│ uint32 大端            │ length = payload_len      │ 文件分片时才有    │
└───────────────────────┴──────────────────────────┴─────────────────┘
```

- 服务端**只回 binary 帧**（`opcode=0x2`），text 帧会被当旧客户端处理并回 system 提示。
- 单条消息上限 8 MiB（`max_message_bytes`），单连接待发送队列上限 8 MiB（`max_pending_bytes`），
  文件分片 4 MiB —— 所以**同时并发多个上传/预览会撑爆队列被断开**（web 前端为此把预览并发限制为 1）。
- 服务端可**主动推送**（私聊/群聊/频道消息、删除通知、系统提示），接收侧必须是持续的读循环
  （Qt 侧即 `QWebSocket::binaryMessageReceived` 信号，天然异步，不需要手写线程）。
- **TLS**：`wss://` 必须能建 TLS。`src/main.cpp` 启动时 `QSslSocket::setActiveBackend("schannel")`，
  用 Windows 自带的 SChannel 后端，**不需要随包分发 OpenSSL DLL**（Qt 默认优先 openssl，要 `libssl-3-x64.dll`）。

实测（用临时探针 QWebSocket 直连生产，探针已删除）：

```
TLS backends: cert-only openssl schannel | active: schannel
[connected] wss://bakacomm.world/ws
[sent] protobuf=6 bytes (+4 长度前缀), type=show
[recv] 4B payload_len=56, 实际=56 OK
[envelope] type=system content=You must be logged in to view your chat list.
```

（上面这段是当时的验证记录，程序已删除；服务端行为有疑时再临时写探针即可。）

## 2. Envelope 字段总表

> 全部字段都在同一个 `Envelope` 里，用 `type` + 按需字段的组合表达所有请求/响应。
> 字段号不可更改（后端与 web 前端共用）。

| # | 字段 | 类型 | 用途 |
|---|---|---|---|
| 1 | `type` | string | 消息类型（必填，决定分发） |
| 2 | `content` | string | 系统提示 / 消息正文（推送场景） |
| 3 | `target_UID` | int32 | 私聊对象 / 群 id / 频道 id |
| 4 | `message` | string | 发送的消息正文 |
| 5 | `message_id` | int32 | 消息 id（删除、回复、分页游标） |
| 6 | `peer_id` | int32 | 会话对端 id（历史请求/响应） |
| 7 | `before_id` | int32 | 历史分页游标（0/缺省 = 取最新一页） |
| 8 | `has_more` | bool | 历史响应：还有更旧的消息 |
| 9 | `group_UID` | int32 | 群相关 / 群聊推送 |
| 10-14 | `target_user_UID` `requester_UID` `group_name` `new_name` `promote` | | 群管理 |
| 15-20 | `friend_UID` `sender_UID` `email` `apply_message` `remark` `accept` | | 好友 |
| 21-25 | `UID` `username` `password` `token` `user{id,username}` | | 登录/注册 |
| 26 | `sender_name` | string | 推送消息的发送者昵称 |
| 27 | `timestamp` | string | 服务端时间，**UTC** `"YYYY-MM-DD HH:MM:SS"` |
| 28-29 | `reply_to_message_id` `reply_to{message_id,sender_name,content}` | | 回复引用（只一层） |
| 30-31 | `file_name` `meta(FileChunkMeta)` | | 文件 |
| 32 | `messages` | repeated ChatItem | 历史响应 |
| 33-43 | `community_id` `channel_id` `category` `description` `avatar` `role` `is_channel` `communities[]` `channels[]` `members[]` `theme` | | 社区/频道/主题 |
| 44-48 | `file_meta` `transfer_info` `transfer_id` `file_id`(string) `files[]` | | 文件系统 |
| 49-52 | `avatar_id` `is_file` `file_size` `contacts[]` | | 头像 / 文件消息 / 联系人 |
| 53-54 | `community_avatar_id` `community_banner_id` | | 社区图片 |
| 55 | `chunk_index` | int32 | 分片下载块号 |

`ChatItem`：`message_id(1) sender_UID(2) sender_name(3) is_group(4) content(5) timestamp(6)
reply_to_message_id(7) reply_to(8) is_file(9) file_id(10) file_name(11) file_size(12)`

## 3. 请求清单（客户端 → 服务端，按本期优先级）

| 阶段 | type | 关键字段 |
|---|---|---|
| 连接后 | `verify_token` | `token`（7 天滑动过期） |
| 登录 | `login` | `UID`+`password` 或 `email`+`password` |
| 注册 | `register` | `username` `email` `password` |
| 会话列表 | `show_contacts` | → `contact_list_response`（`contacts[]`） |
| 历史 | `history_request` | `peer_id` `before_id` `is_channel` |
| 私聊 | `private_chat` | `target_UID` `message` `reply_to_message_id` |
| 群聊 | `group_chat` | `target_UID`(=群id) `message` |
| 频道 | `channel_chat` | `target_UID`(=频道id) `message` |
| 删除 | `delete_message` | `message_id`（仅本人、3 分钟内） |
| 社区 | `show_communities` / `show_community_channels` / `show_community_members` | `community_id` |
| 好友 | `show_friend_requests` / `add_friend` / `accept_friend` / `reject_friend` / `remove_friend` / `set_friend_remark` | |
| 心跳 | `heartbeat` | → `heartbeat_ack`（`content="pong"`） |
| 退出 | `logout` / `exit` | `exit` 会关闭连接 |

## 4. 响应与推送清单

| type | 说明 | 关键字段 |
|---|---|---|
| `system` | 一切文本提示/错误/文本列表 | `content` |
| `login_success` | 登录成功 | `token` `user{id,username}` `avatar_id` |
| `contact_list_response` | 联系人（好友+群） | `contacts[]` |
| `history_response` | 历史分页 | `peer_id` `messages[]` `has_more` |
| `private_chat` | **推送**私聊 | `content` `message_id` `sender_UID` `sender_name` `timestamp` |
| `Group_Chat` | **推送**群聊（注意大小写） | 同上 + `group_UID` |
| `Channel_Chat` | **推送**频道（注意大小写） | 同上 + `group_UID`(=频道 id) |
| `delete_message` | 消息被删通知 | `message_id`（群/频道还带 `group_UID`） |
| `heartbeat_ack` | 心跳应答 | `content="pong"` |
| `community_list_response` / `channel_list_response` / `community_member_list_response` | 社区数据 | `communities[]` / `channels[]` / `members[]` |
| `file_*` | 文件系统（后续阶段） | `file_meta` `transfer_info` `meta` |

> 推送消息的文件版本额外带 `is_file=true` `file_id`(string) `file_name` `file_size`；
> 回复版本额外带 `reply_to_message_id` + `reply_to{...}`。

## 5. 登录 / token 流程

```
[启动] QSettings 里读 token
   ├─ 有 token → 连接 → verify_token{token}
   │      ├─ login_success → 进入主界面
   │      └─ system("Invalid or expired token...") → 清 token，显示登录页
   └─ 无 token → 连接 → 显示登录页 → login/register
login_success 后：保存 token（QSettings）→ show_contacts → 渲染会话列表
```

关键系统提示（用于判定状态，注意是**文本匹配**，后端没有结构化错误码）：

| 文本 | 含义 |
|---|---|
| `Registration successful.*UID (\d+).*?or (\S+)\.` | 注册成功，可解析出 UID |
| `Incorrect password for UID [<UID>].` | 密码错 |
| `Account with UID [<UID>] does not exist.` | 账号不存在 |
| `You must be logged in to ...` | 未登录（token 失效或没登） |
| `Token expired` / `Invalid or expired token` | token 失效 → 清本地 token |
| `Your account is logged in elsewhere, you have been kicked offline.` | 被顶下线 |
| `Message sent. Message ID: (\d+)` | 发送成功回执，`message_id` 用于替换本地占位消息 |

## 6. 聊天历史分页（重点，与后端实现严格对齐）

后端实现：`chat_handler.cpp::chat_history()` → `message_repo::get_history_page()`。

- **每页固定 10 条**（后端 `kPageSize = 10`，客户端不要自己传 limit）。
- 游标是 `message.id`（自增＝时间顺序），不是时间戳。
- `before_id = 0` 或缺省 → 取**最新一页**；`before_id = N` → 取 `id < N` 的更旧一页。
- 响应里的 `messages[]` 是**时间正序（旧→新）**，`has_more=true` 表示还能继续往前翻。
- 会话类型判定：
  - 频道：请求必须带 `is_channel = true`，服务端按 `type='channel'` 查；
  - 群聊：客户端**不发**类型字段，服务端用「当前账号的内存群列表」判断，
    所以拉群历史前必须先 `show_contacts` / 拉过群列表，否则会被误判成私聊查不到数据；
  - 私聊：双向会话（A→B 与 B→A 一起按 id 排序）。
- 消息保留期 **7 天**（后端定时删 `send_time < NOW()-7 DAY`）。

客户端会话对象（对齐 web 前端 `backendClient.js` 的 `ensureConversation`）：

```cpp
struct Conversation {
    Kind kind;            // Private / Group / Channel
    int  id = 0;
    QString name;
    QList<Message> messages;
    bool loaded = false;  // 是否已成功拉过首屏
    bool loading = false; // 请求在途（防重入）
    bool hasMore = true;
    int  oldestId = 0;    // 已加载的最旧 message_id，上滑时作为 before_id
};
```

流程：

```
选中会话 → if (!loaded && !loading) requestHistory(conv, beforeId = 0)
响应     → 按 message_id 去重后合并 → 排序 → oldestId = min(message_id)
         → loaded = true, loading = false, hasMore = has_more
滚动到顶部 → if (hasMore && !loading && oldestId > 0) requestHistory(conv, oldestId)
```

注意点：

- 请求是**异步 + FIFO**：web 前端用 `historyQueue`（请求顺序 → 响应用 `peer_id` 回填）。
  Qt 侧建议给每个请求带自增 `request_id`（或直接按 `peer_id` 匹配，因为同一会话被 `loading` 挡住不会并发）。
- 失败时后端只回 `system("Failed to load chat history.")`，**没有 `has_more`**，
  必须靠文本匹配把 `loading` 复位，否则该会话永远卡住。
- 本地乐观消息（自己刚发的）用临时 id 占位，收到 `Message sent. Message ID: n` 后替换为真实 `message_id`，
  否则再拉历史会出现重复。

## 7. 心跳与重连

- `heartbeat` → `heartbeat_ack`（`content="pong"`）。生产端是否强制超时断开取决于后端 `use_heartbeat`，
  客户端按 30~60s 定时发心跳即可（服务端默认 `heartbeat_interval=60`）。
- 断线重连：`QWebSocket` 的 `disconnected()` → 退避重连（1s/2s/4s… 上限 30s）→ 回连后用 token `verify_token`，
  再 `show_contacts` 刷新，本地会话缓存保留但 `loaded/hasMore` 不清（重连后缺失的消息靠重新拉历史补）。

## 8. 文件传输（后续阶段）

- 客户端上限：单条 WS 帧 8 MiB；服务端分片 4 MiB（`file_storage.chunk_size`）。
- 上传：`file_upload_init` → 若干个 `file_chunk`（帧尾带文件数据）→ `file_upload_done`。
- 下载：`file_download_init` → 按 `chunk_index` 循环 `file_download_chunk`。
- 支持 `file_upload_resume` 断线续传、`file_transfer_pause` 暂停/继续/取消。
- 静音点：**预览下载并发要限制为 1**（web 端踩过的坑：两个 4 MiB 预览 + 协议开销 > 8 MiB 待发送上限，连接被断）。

## 9. Qt 客户端架构规划

> 硬约束见 [`开发约束.md`](开发约束.md)：C++17、纯 C++ 建 UI（布局管理器）、不用 `.ui`、
> 每个页面独立 `QWidget` 子类、QSS 只做视觉、Signal/Slot 通信、单文件不超 400 行。
> 下面目录里的每个 UI 类都对应一个独立 `QWidget`，组合用 `QHBoxLayout/QVBoxLayout/QSplitter`。

```
src/
├── net/
│   ├── WsClient.h/.cpp        # QWebSocket 封装：连接/TLS/重连/心跳、收发二进制帧
│   ├── PacketCodec.h/.cpp     # 4B payload_len + Envelope <-> QByteArray
│   └── RequestTracker.h/.cpp  # 请求队列（historyQueue 等价物）、超时、loading 复位
├── model/
│   ├── Session.h              # 当前账号（uid/name/avatar/token）
│   ├── ConversationStore.h    # conversations[QString key] = Conversation（key = "private:12"）
│   ├── ContactModel.h         # QAbstractListModel：会话/联系人列表
│   └── MessageModel.h         # QAbstractListModel：消息列表（分页插入 + 消息分组）
├── ui/
│   ├── LoginDialog.h/.cpp     # 登录 / 注册
│   ├── MainWindow.h/.cpp      # 左侧会话栏 + 中间消息区 + 右侧成员区
│   ├── MessageDelegate.h/.cpp # 消息行绘制（头像/昵称/时间/回复/文件/反应）
│   └── Composer.h/.cpp        # 输入框（Enter 发送 / Shift+Enter 换行 / IME 安全）
└── util/
    └── TimeFormat.h           # UTC "YYYY-MM-DD HH:MM:SS" → 本地时区
```

实现顺序（每步都能跑起来验证，避免一次性堆完再调）：

1. `PacketCodec` → `WsClient`（QWebSocket 封装），先做一个「连接 → 发 `show` → 打印返回」的最小调试入口；
2. `LoginDialog` + `verify_token`/`login`/`register` + token 持久化；
3. `ContactModel`（`show_contacts`）+ `MainWindow` 骨架；
4. 历史分页 + `MessageModel`（含 `has_more` 上滑加载、scrollTop 补偿）；
5. 发送（乐观消息 + `Message sent. Message ID` 回执替换）+ 实时推送（`private_chat` / `Group_Chat` / `Channel_Chat`）；
6. 群/社区/好友管理；
7. 文件传输（分片 + 进度 + 续传）。

与 web 前端的对应关系（可直接对照移植逻辑）：

| web 前端 | Qt 侧 |
|---|---|
| `frontend/src/backendClient.js` 的 `send()` / `historyResponse()` / `regroup()` / `recordOf()` | `WsClient` + `ConversationStore` |
| `frontend/src/protobufProtocol.js`（`encodePacket`/`decodePacket`，4B 长度） | `PacketCodec` |
| `App.vue` 的 `scrollChat()`（`scrollTop < 12` 触发加载更多） | `MessageModel` + `QScrollBar` 回调 |
| `frontend/src/data/i18n.js` | 后续需要再做多语言 |

## 10. 约定与红线

- **字段号永远不要改**，加字段只能追加新号（后端与 web 端共享同一份 `message.proto`）。
- `proto/message.proto` 是**副本**：后端改了要同步过来（`copy ../-----server/src/proto/message.proto proto/`）。
- 时间统一 UTC 存储、本地显示；不要用 `QDateTime::currentDateTime()` 直接给消息打时间戳。
- 所有 UI 文本走 UTF-8；`QStringLiteral` + `tr()` 便于后续 i18n。
- 中文在 Windows 控制台输出乱码属于代码页问题（`chcp 65001`），不影响程序内部数据。
