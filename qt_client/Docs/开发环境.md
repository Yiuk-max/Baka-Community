## 2. protobuf 3.20.3（已安装，可复现）

### 为什么是 3.20.3

- 3.20.x 是**最后一个不依赖 Abseil** 的版本，源码自带 CMake 工程，直接编即可；
- 3.21+/v22+ 起必须编 Abseil，MinGW 下额外依赖和坑明显更多；
- 我们只需要 proto3 基础特性（`message` / `repeated` / 标量），3.20.3 完全够用；
- **必须用 Qt 自带的 MinGW 13.1 编译**：protobuf 是 C++ 静态库，编译器/运行库不一致会导致符号或 `std::string` ABI 问题。

### 安装位置：机器级 `D:\libs\protobuf-3.20.3`（不入版本库）

> 之前放在工程内的 `qt_client/third_party/protobuf`，结果“清目录”时被连坐删除。
> 现在改到**机器级目录**，与工程解耦；`CMakeLists.txt` 默认读 `D:/libs/protobuf-3.20.3`，
> 也可用 `-DPB_PREFIX=...` 覆盖，工程内若有 `third_party/protobuf` 会自动回退。

```
D:\libs\
├── protobuf-3.20.3\        # 安装前缀（21 MB）：bin/protoc.exe、lib/libprotobuf.a、include/、lib/cmake/
└── src\protobuf-cpp-3.20.3.tar.gz   # 源码包（4.6 MB，保留着，避免再下载）
```

### 重编步骤（已执行，备份只在删了 `D:\libs` 时才需要）

> ⚠️ **不要再自己下载**：本机到 GitHub Releases 只有 ~35 KB/s，4.6 MB 要下 2 分钟。
> 源码包已在 `D:\libs\src\protobuf-cpp-3.20.3.tar.gz`，直接用。

```bash
export PATH="/d/QT/Tools/CMake_64/bin:/d/QT/Tools/Ninja:/d/QT/Tools/mingw1310_64/bin:$PATH"
cd /d/libs/src && tar -xzf protobuf-cpp-3.20.3.tar.gz

# 配置（用的是 protobuf-3.20.3/cmake 子目录）
cmake -S D:/libs/src/protobuf-3.20.3/cmake -B D:/libs/build-pb -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX=D:/libs/protobuf-3.20.3 \
  -Dprotobuf_BUILD_TESTS=OFF \
  -Dprotobuf_BUILD_SHARED_LIBS=OFF \
  -Dprotobuf_BUILD_PROTOC_BINARIES=ON \
  -DCMAKE_C_COMPILER=D:/QT/Tools/mingw1310_64/bin/gcc.exe \
  -DCMAKE_CXX_COMPILER=D:/QT/Tools/mingw1310_64/bin/g++.exe

# 编译安装：用 -j4（约 2 分钟）。千万不要 -j16/-j32，会把 CPU 拉满
cmake --build D:/libs/build-pb --target install -j4

# 装完清掉中间产物（只留安装前缀）
rm -rf D:/libs/build-pb D:/libs/src/protobuf-3.20.3
```

### 产物校验

```bash
D:/libs/protobuf-3.20.3/bin/protoc.exe --version   # libprotoc 3.20.3
D:/libs/protobuf-3.20.3/lib/libprotobuf.a          # 静态库（MinGW 13.1 编译）
```

### CMake 里的接线方式（`CMakeLists.txt`）

```cmake
set(PB_PREFIX "D:/libs/protobuf-3.20.3" CACHE PATH "protobuf install prefix")
# 机器上没有时可回退到工程内 third_party/protobuf
set(Protobuf_INCLUDE_DIR "${PB_PREFIX}/include")
set(Protobuf_LIBRARIES   "${PB_PREFIX}/lib/libprotobuf.a")
set(Protobuf_PROTOC_EXECUTABLE "${PB_PREFIX}/bin/protoc.exe")
find_package(Protobuf REQUIRED)
protobuf_generate_cpp(PROTO_SRCS PROTO_HDRS "${CMAKE_CURRENT_SOURCE_DIR}/proto/message.proto")
```

`message.pb.h` 会生成到 `build/`（已加入 include 路径），改完 `.proto` 重新构建即可自动重生成。

> 变量名不要用 `PROTOBUF_ROOT`：CMake 3.30 的 `CMP0144` 会抢这个变量的语义并告警，用 `PB_PREFIX` 规避。

### 不走的三条路（已踩过）

| 方案 | 结果 |
|---|---|
| `vcpkg install protobuf` | 装到的是 **7.36.2 + abseil**，`libprotoc` 的 `php_generator.cc` 在 MinGW 下编不过；而且 vcpkg 默认 `-j33`，**CPU 直接 100%**；它还会夹用 msys64 的 GCC（UCRT），与 Qt 的 13.1 ABI 不一致 |
| `protoc-*-win64.zip`（Google 官方预编译） | 里面**只有 `protoc.exe`，没有 C++ 库**（`lib` 目录不存在），无法链接 |
| msys64 `pacman -S mingw-w64-ucrt-x86_64-protobuf` | 库是 GCC 15/UCRT 编的，与 Qt 的 GCC 13.1 可能符号不兼容，不推荐 |

### 升级 / 重装

删掉 `D:/libs/protobuf-3.20.3` 后重跑上面“重编步骤”即可（源码包已在本机，无需联网）。

## 3. Qt WebSockets（已安装）

`D:\QT\6.11.1\mingw_64` 里已有 `bin\Qt6WebSockets.dll` 与 `lib\cmake\Qt6WebSockets\*`，
`CMakeLists.txt` 把它和 Multimedia 一起列为**必需组件**：没装的话 configure 阶段直接报
`Could NOT find Qt6WebSockets`，不会拖到编译时才出错。

> 若换机器后没装：运行 `D:\QT\MaintenanceTool.exe` → Add or remove components →
> `Qt` → `Qt 6.11.1` → 勾选 **Qt WebSockets**、**Qt Multimedia**（Additional Libraries 分类）→ 重新 configure。

### TLS 后端：用 schannel，不依赖 OpenSSL DLL

Qt 6.11 自带三个 TLS 插件（`plugins\tls`）：`qcertonlybackend`、`qopensslbackend`、`qschannelbackend`。
客户端连 `wss://` 必须能建 TLS，而 Qt 默认优先 `openssl` —— 它要求 `libssl-3-x64.dll` / `libcrypto-3-x64.dll`，
Qt 安装包**不带**这两个 DLL（本机凑巧 `C:\Windows\System32` 里有，是 MySQL 装的，换机器就没有）。

所以启动时（`src/main.cpp` 调 `tlssetup::initialize()`，实现在 `src/net/TlsSetup.cpp`）固定切到系统后端：

```cpp
#ifdef Q_OS_WIN
    QSslSocket::setActiveBackend(QStringLiteral("schannel"));
#endif
```

实测两种后端都能通（临时探针分别指定 `openssl` / `schannel` 各跑一次，探针已删除），但**只用 schannel 才能免 OpenSSL 分发**。

# origin  https://github.com/Yiuk-max/Baka-Community.git (fetch)

## 7. 后端相关（本期不在本机跑）

**结论：后端无法在本机 Windows 上编译运行。**

- `include/total.h` 无条件 include `<sys/epoll.h> <unistd.h> <arpa/inet.h>` 等 Linux 头；
- 仓库根的 `CMakeLists.txt` 写死 `include_directories(/usr/include/mysql-cppconn)` 并链 `mysqlcppconn`；
- CMake 把 `src/net_core`（epoll）和 `src/net_core_ws`（Boost.Asio）编进同一个二进制，`net_layer` 只是运行时开关。

因此客户端**直接连生产环境** `wss://bakacomm.world/ws` 做联调。

本机环境现状（仅备查，客户端开发用不到）：

| 项 | 状态 |
|---|---|
| MySQL 3306 | 在跑（后端才需要） |
| Redis 6379 | 未启动 |
| 8080 | 被 `ApplicationWebServer.exe` 系统服务占用 |
| Docker Desktop | 已装，WSL2/daemon 处于 Stopped |
| WSL 发行版 | 只有 `docker-desktop`，无 Ubuntu |

若以后要本地跑后端：启动 Docker Desktop → 起一个 Ubuntu 容器（装 boost/protobuf/mysql-cppconn/redis-plus-plus），
把 `configure.json` 里 `net_layer` 保持 `websocket`、`redis.enabled` 视情况改 false，映射 8080（需先避开上面那个占用）。
