# 断线重连实施计划

状态：已实施核心功能（自动重连 + token 重新认证 + 心跳失联检测 + 恢复同步）。
离线发信自动重发、请求队列、全账号离线消息同步等第一版不做的项仍不提供。
范围：Qt 桌面客户端；复用现有 WebSocket + protobuf，不修改服务端协议。

## 1. 用户行为与范围

- 已登录用户遇到断网、服务器重启、连接异常、心跳超时：自动重连并用 token 重新认证。
- 临时断线不退出主窗口、不清联系人和聊天内容，保留输入草稿、本地媒体缓存及下载进度。
- 业务认证恢复前不允许发送聊天、审批、改资料或发文件请求；本地图片/视频仍可打开。
- 恢复后刷新列表、校验当前会话权限、同步当前聊天记录，再继续符合条件的下载任务。
- 主动登出、被顶下线、关闭程序后停止重连，不自动抢回账号。
- token 明确失效：停止自动恢复、清 token、回登录窗口；不循环验证失效 token。
- 只使用现有状态栏做简短状态提示，不新增说明面板、重连弹窗或辅助按钮。
- 首版不做离线发信队列、不自动重发未确认聊天消息、不引入通用请求事件总线。

## 2. 当前代码与问题

| 位置 | 现状 / 风险 |

## 3. 状态机与职责

### ChatClient（主线程，唯一重连策略拥有者）

```text
Stopped
  └─ start / 用户明确登录 → Connecting
Connecting
  ├─ 握手成功 → Authenticating（需要 token/显式认证）
  │             或 Unauthenticated（无 token，显示登录表单）
  └─ 网络失败/连接超时 → ReconnectWaiting
Authenticating
  ├─ login_success → Synchronizing → Ready
  ├─ 网络断开/认证超时 → ReconnectWaiting（保留 token）
  └─ 明确 token 无效/被顶下线 → Unauthenticated（禁止后台自动登录）
Ready / Synchronizing
  ├─ 网络断开/心跳超时 → ReconnectWaiting
  └─ 登出/被顶下线/关闭 → Unauthenticated / Stopped
ReconnectWaiting
  ├─ 到期 → Connecting
  └─ 登出/被顶下线/关闭 → 停止定时器，失效旧代次
```

- 区分 `transportConnected`、`authenticated` 和 `sessionReady`。
- `isConnected()` 保留表示底层连接；新增 `isAuthenticated()` / `isReady()` 供业务调用方使用。
- 保留断线前 UID、昵称作为显示身份；不能以 uid()>0 代表服务端已登录。
- 登录意图和当前状态分开：记录是否允许自动恢复、是否显式登出、是否退出程序。
- 拟新增 `sessionLost(reason)`、`sessionRestored()`、`readyChanged(bool)`、`reconnectScheduled(attempt,delay)`。
- `loginSucceeded` 只驱动首次/不同账号登录初始化；同账号恢复使用单独信号，不重复触发登录窗口 accept。
- 同账号 token 恢复必须核对服务端 UID；若与保留身份不同，停止恢复并清旧账号上下文，不能混用。

### WsCore（网络线程，只执行传输动作）

- 不再自己决定重试时机；负责 open / abort / close / sendFrame，以及传输状态回传。
- 一次连接尝试对应一个 generation；重试时销毁/替换旧 QWebSocket，旧回调捕获自己的代次。
- connected / frameReceived / transportLost / sendResult 带代次，ChatClient 丢弃旧代次事件。
- errorOccurred 记录原因；和 disconnected、连接超时合并为本代次一次 transportLost。
- abort 必须终止 Connecting 状态；不能因 reconnect() 只接受 UnconnectedState 而永远卡住。
- 跨线程排队的发送也带代次，防止旧业务帧在新连接上执行。

## 4. 自动重试与超时（建议默认值）

| 项目 | 默认值 |
|---|---|
| 首次网络失败后的等待 | 1 秒 |
| 指数退避 | 1 / 2 / 4 / 8 / 16 / 30 秒，封顶 30 秒 |
| 随机抖动 | 每次 ±20%，最终不超过 30 秒 |
| 单次连接超时 | 10 秒，涵盖 DNS/TCP/TLS/WS 握手 |
| token 认证超时 | 10 秒，从实际发出认证请求开始计时 |
| 已登录自动恢复 | 持续重试直到成功、明确认证失败或用户停止 |
| 稳定期 | Ready 持续 30 秒后重置退避计数，防握手成功后立刻断线形成高速循环 |
| 业务心跳 | 每 30 秒一次，最多一个等待中的 heartbeat |
| 心跳应答超时 | 15 秒；超时 abort 当前连接进入退避 |

- 所有超时只使用单调时钟（QElapsedTimer/steady clock），不受系统时间调整影响。
- 休眠恢复不补发积压心跳：发现过期先终止旧连接再重连。
- 第一阶段不依赖平台网络检测；即使系统显示在线也以真实连接为准。
- TLS 证书校验/无效 URL/不支持的 scheme 等确定配置错误停止重试并显示已有状态栏错误；不忽略 SSL 错误。
- 自动恢复期间密码/注册/验证码请求不盲重放；用户可明确重新提交，显式请求优先于存储 token。
- 未登录且无 token 的启动连接失败可在登录页后台退避；用户关闭页/应用即停止。
- 有 token 的启动等待窗第一次失败可退回登录表单，但不得自动提交覆盖用户正在编辑的凭据；
  用户提交显式认证时切换登录意图、取消后台 token 恢复；用户取消/关闭时撤销所有后台尝试。

## 5. 认证边界与退出

- 握手成功后先 heartbeat（可选）和 verify_token；认证前不发 show_contacts、history 或 file_*。
- 根据服务端当前明确文本 `Invalid or expired token.` / `Token expired, please login again.` 判断 token 无效。
- 网络错误、认证超时、服务端未知错误保留 token；中止本代次后退避，不把未知提示误译为“登录过期”。
- 无明确错误码时仅匹配已核对的认证回执，未识别提示不直接消耗认证状态，等待成功/超时兜底。
- 主动登出先禁止自动恢复、撤销定时器和在途认证，再清 token/账号；必要时断开旧 socket，
  避免登出后旧 login_success 把账号重新登录。
- 被顶下线先设置禁止恢复，再沿现有通知 → 登录窗口流程；随后 close/error 不能启动新重连。
- 析构停止全部定时器，失效 generation，网络线程内 abort/close 后 quit/wait；不从停止回调重新调度。
- 不在日志中记录 token、密码、验证码或认证 Envelope 全文。

## 6. 业务发送策略：不做隐式重放

- ChatClient 统一拦截：认证消息/heartbeat 走内部允许列表，其余仅在所需会话阶段放行。
- `send()` 增加明确的接收结果（bool 或 requestRejected），页面先确认允许发送，再创建乐观消息。
- 网络线程 sendFrame 返回实际接收/拒绝结果；在检查与实际发送之间断线也能解除 loading。
- 本地已交给 socket 不等于服务端已提交，不能承诺“消息送达”。
- 断线前未收到确认的消息标为“结果未知”，从新回执 FIFO 中移除；保留正文供用户判断后手动重发。
- 同步历史时只用真实 message_id 去重，不按正文/时间猜测未知消息是否已提交，避免错认重复文本。
- 群/频道消息的本人推送也不能确认上一代次的未知乐观消息。
- 审批、创建社区、改头像等非幂等操作不重放；中断后解除 busy、提示结果不确定，通过刷新核对。
- 用户输入草稿保留；断线时禁用发送而非禁用整个输入框，不影响复制/本地编辑。

## 7. 恢复同步顺序与历史一致性

```text
新连接 token 成功（仍未 Ready）
  → 标记同账号 authenticated
  → show_contacts / show_communities / 好友申请
  → 等 contact_list_response（服务端群历史依赖已加载群列表）
  → 核对当前私聊/群/社区仍存在及权限
  → 当前社区拉频道与成员；存在的频道再拉历史
  → 当前可见会话完成最新历史刷新
  → Ready，开放业务发送，触发下载恢复和媒体预取
```

- Synchronizing 阶段允许内部只读同步请求，不开放用户变更请求；同步失败有独立超时/重试，
  不在传输健康时无限重建 socket。达到重试上限后退出同步到可见的失败状态，仍允许登出。
- 列表刷新更新数据而不主动跳主页，不重建主窗口，不丢输入草稿、打开的社区和成员面板状态。
- 丢失资格的会话退回主页；对应旧聊天不能继续发送或恢复频道请求。
- 清理旧代次的 history loading、社区 pendingChannels/pendingMembers、审批列表请求及过期延时回调。
- 历史接口只有 before_id、每页 10 条，没有 after_id、请求 ID、删除增量或快照版本。
- 第一版采用“断线后当前会话首屏重新校准”：保留草稿，成功取得最新一页后替换服务端历史行，
  排除旧的乐观确认队列；旧的更早页失效，用户上滑重新分页。不要仅追加最新 10 条并宣称完整补齐。
- 显示旧记录可一直保留到新页返回；结果未知的本地消息独立保存，不混入服务端历史去重集合。
- 未读位置/长断线的全部离线消息/跨所有会话历史合并不在第一版承诺范围。
- 新历史响应和实时推送按 message_id 合并；新页返回前已收到的新消息要保留，不能被替换掉。
- 群/私聊数字 ID 碰撞、频道标记、响应归属依靠本地会话 key（kind:id）、generation 和串行在途登记。
  协议缺少 request_id 时对无法消歧的历史请求限流，不能只看 peer_id 并行更新两个页面。

## 8. 下载、媒体和头像恢复

- 传输层断开即中断下载、停止新分片；Ready 之前 FileDownloader 不得仅凭 isConnected()+UID 开始。
- 同账号 sessionRestored 不调用 MediaStore::setUser 清缓存，只更新任务状态并重启可见区检查。
- 区分 Interrupted 原因：只自动恢复“本次网络断线”导致的未完成任务；用户 Paused/Canceled/Failed 不动。
- 本次手动下载（含大视频/普通文件）从本地完整分片断点重新 download_init，复用原 taskId 和目标目录。
- 恢复核对大小/hash/chunkSize；保持单分片在途和当前下载优先级，取消后的迟到回执不能复活。
- 静默头像任务断线被丢弃时需释放 AvatarStore 等待项，再按最新列表重新 ensure，避免永远卡等待。
- 静默聊天媒体只恢复当前可见预加载范围；旧页排队任务不因重连被全量恢复。
- 进程重启或显式登出后再登录：读回断点但默认不自动继续大文件，由用户点击恢复。
- 同一普通文件重新认证后仍使用原 targetPath，不因系统下载目录/环境变量变化迁移半文件。
- 本地完整图片/视频不受离线限制，仍通过系统默认应用打开。
- 当前头像/社区图片上传断线保持失败；不自动重新上传或重复 set_avatar/modify_community。

## 9. 文件与分步实施

按职责小步交付，保留现有修改和注释；单 .cpp 目标 ≤400 行：

1. **状态模型与信号**：ChatClient 状态枚举、认证/就绪标记、登录意图和 generation；
   将当前 400 行以上的认证处理拆到 `ChatClientAuth.cpp`，连接恢复放 `ChatClientReconnect.cpp`。
2. **网络生命周期**：WsCore 连接代次、单次失联事件、abort、连接超时、跨线程发送回执。
3. **重试/认证/心跳**：退避、稳定期、token 明确失败分流、心跳超时、登出/顶号/关闭中止。
4. **页面恢复**：MainWindow 单独的恢复接线文件、main 登录流程防重复、ChatPage 会话同步和发送保护、
   CommunityPage 清理在途队列；状态栏简单显示，不增加辅助按钮或说明区域。
5. **下载协同**：FileDownloader 就绪门控、Interrupted 原因、MediaStore 同账号恢复、头像等待项清理。
6. **离线测试与文档**：本地 QWebSocketServer 故障注入，确保已有附件测试保持通过。

不引入新第三方依赖，不修改 protobuf 字段号，不自动提交或连接生产服务。

## 10. 验收与测试

新增独立离线测试，缩短可注入定时参数，退避抖动使用可控随机源，避免测试等数分钟：

- [ ] 正常启动、无 token 登录、有 token 自动登录及验证码流程不回归。
- [ ] 服务器拒绝连接、DNS/握手失败、Connecting 卡死能超时；只有一条重试计时链。
- [ ] error+disconnected 连续触发仅处理一次；旧 generation 回调和待发送帧被丢弃。
- [ ] 断线后重连必须 verify_token，认证及列表/历史同步前不发业务或下载请求。
- [ ] 认证超时保留 token；明确 token 失效只回登录一次，不无限认证。
- [ ] 连上即断的抖动场景不清退避，Ready 稳定后才重置计数。
- [ ] 心跳无应答但 socket 未关闭时能发现失联；晚到 heartbeat_ack 不能复活旧代次。
- [ ] 登出、顶号、关闭程序，以及定时器到期同时发生时，禁止重连和迟到登录成功。
- [ ] 主窗口、会话、输入草稿保留；原账号状态不串到不同账号。
- [ ] 断线期间发送不产生假成功；未确认消息不自动重发、不被下一次 FIFO 回执错误确认。
- [ ] 同步失败释放 loading；群列表先于群历史；权限丢失正确处理。
- [ ] 缺失超过一页、对端撤回、同步中来新消息、频道/私聊 ID 相同均无误归属。
- [ ] 多分片下载恢复内容/hash 正确；暂停/取消/失败及其他账号任务不会被自动恢复。
- [ ] 头像、静默媒体、进度卡及系统图片打开原有离线测试通过。
- [ ] 构建使用现有固定工具链 -j4；不模拟键鼠，不操作生产账号。

第一版明确不提供：离线发信自动队列、恰好一次投递、全账号离线消息全量同步、
通用上传自动续传、断线后的自动账号抢占。

## 11. 实施进度

已完成并通过构建与离线测试（Qt 6.11.1 + MinGW 13.1，`-j4`）：

- `net/WsCore.*`：每次 `start()` 是一次新的连接尝试（generation+1），旧 socket 回调作废；
  单次连接总超时（默认 10s，可用 `BAKA_CONNECT_TIMEOUT_MS` 覆盖）；error+disconnected
  合并为每代次一次 `disconnected`；`sendFrame(generation, ...)` 拒绝旧代次帧。
- `net/ChatClient.*` + `net/ChatClientAuth.cpp` + `net/ChatClientReconnect.cpp`：
  - 状态机拆成“传输已连接 / 已认证”两件事；`isAuthenticated()` 供发送与下载做门控；
  - 断线后 `uid>0` 时重连必走 `verify_token`，同账号成功发 `sessionRestored`（不触发首次登录初始化）；
  - 指数退避 1s→30s + ±20% 抖动（`BAKA_RECONNECT_BASE_MS` / `BAKA_RECONNECT_MAX_MS` 可缩短）；
  - 心跳 30s（`BAKA_HEARTBEAT_INTERVAL_MS`），无应答 15s（`BAKA_HEARTBEAT_TIMEOUT_MS`）主动判失联；
  - 明确 token 失效才回登录页；网络错误/认证超时保留 token 并重试；登出/被顶下线/析构不再重连；
  - `send()` 返回 bool 并拦截未认证业务消息；`cancelAutomaticLogin()` 供启动等待窗退回手动登录。
- 页面恢复：`MainWindow` 用 `readyChanged` 点在线状态，`sessionRestored` 重新拉列表；
  `ChatPage` 断线复位 loading、作废旧确认队列，恢复后重拉当前会话首屏（草稿保留）；
  `CommunityPage` 断线清空频道/成员在途队列，恢复后重拉。
- 下载恢复：`FileDownloader` 增加 `resumeNetworkInterrupted()`，同账号恢复后自动续传
  本次断网中断的磁盘任务；`reset()` 丢弃内存任务时会通知头像等待方重新请求；下载/媒体门控改为已认证。

离线测试：`tests/reconnect_behavior.cpp`（本地 WebSocket 假服务，`ctest` 通过）覆盖
自动重连 + 重新验证 token、登出后不重连、重连时 token 失效回登录且不再重连。
