# 聊天附件下载与缓存实施计划

状态：附件界面、缓存接线及离线交互测试已完成。边界验收仍以第 9 节清单为准，不代表所有异常场景已覆盖。
范围：Qt 客户端的私聊、群聊、社区频道历史及实时附件消息。

## 1. 目标与默认策略

- 图片、小体量视频自动下载至当前登录账号的本地用户文件夹。
- 再次打开会话优先使用磁盘缓存；媒体按可见区域懒加载，不一次解码全部历史附件。
- 大视频不自动下载；普通文件不自动下载。附件右侧或右下角始终展示体积。
- 大小视频均保存至用户文件夹；普通文件保存至系统当前默认下载目录。
- 手动下载的右下角进度卡与 Web 端保持相同基础交互。
- 大文件按服务端分片逐块写磁盘，内存占用不随文件总大小线性增长。
- 不修改 protobuf 字段号，不扩展服务端协议，不引入新第三方依赖。

拟定默认值（可配置，不是服务端限制）：

| 项目 | 默认行为 |
|---|---|
| 图片 | 进入可见区或预加载区后自动下载；不主动扫描未加载历史 |
| 小视频 | `file_size <= 20 MiB` 时自动下载，下载后不自动播放 |
| 大视频 | `file_size > 20 MiB` 时显示封面、大小及下载按钮，点击才下载 |
| 大小未知 | 不按 0 字节误判为小视频；点击后获取真实元数据 |
| 普通文件 | 点击下载按钮后保存至系统下载目录 |
| 预加载区 | 当前可见区域上下各约一屏，仅在当前可见聊天页生效 |
| 图片解码缓存 | 初始预算 64 MiB，按解码后像素占用计费，LRU 回收 |
| 分片并发 | 整条连接最多一个下载分片请求在途 |
| 进度卡终态展示 | 完成、失败、取消后 3 秒自动消失 |

20 MiB 是小视频自动下载阈值的建议默认值；通过 `config.json` 的
`media_cache.small_video_max_bytes` 调整。图片下载仍受服务器文件大小限制、磁盘空间及解码资源保护，
不能简单把超过视频阈值的图片当作普通文件。

## 2. 当前基础与需要替换的部分

- `MessageRow::buildAttachment()` 只有封面和占位下载按钮，没有下载或预览接线。
- `FileDownloader` 已有串行分片拉取，但将整个文件拼到 `QByteArray`，不适合视频和大文件。
- 头像、社区头像和横幅复用该下载器，必须统一调度，不能另建互不知情的并发下载器。
- `AvatarStore` 使用 `<exe>/users/<UID>/avatars/`，新缓存沿用同一账号根目录。
- 服务端默认分片 4 MiB、WebSocket 消息及待发送队列限制各 8 MiB。
- 仓库配置单文件上限 512 MiB，仅作参考；实际以服务端响应和部署配置为准。
- 下载是客户端逐片拉取；最后一个分片后服务端将传输置为 completed，无独立下载完成回执。
- Web 端普通下载将分片拼为 Blob；Qt 只对齐交互，不照搬整文件驻留内存的实现。
- 当前工作区已有 CMakeLists、AvatarStore 修改及旧社区测试删除，实施时保留，不覆盖或恢复这些改动。

## 3. 本地目录与路径规则

```text
<exe>/users/<UID>/
├── avatars/                       # 保留现有头像目录
├── media/
│   ├── images/<fileId>.<ext>       # 图片原文件
│   ├── videos/<fileId>.<ext>       # 小视频自动缓存、大视频手动下载均在这里
│   └── thumbs/<fileId>.<ext>       # 有需要时保存缩略图，不冒充原文件
└── transfers/
    └── <taskId>.json               # 断点、目标路径、原始名、大小、hash、分片信息

<系统 Downloads>/<安全文件名>        # 普通文件最终位置
```

- 下载临时文件放在最终目标同目录：`.<安全文件名>.<taskId>.part`，避免跨盘完成重命名。
- 只有完成大小/hash 校验并成功改名，才更新缓存索引并通知界面“完成”。
- 图片和视频目录只使用 fileId 生成文件主体名；扩展名参考真实 MIME/文件头，图片不伪装格式。
- 普通文件清理目录分隔符、路径穿越、控制字符、Windows 保留名称及末尾点/空格。
- 重名采用 `名称 (1).扩展名` 等规则，不覆盖已有文件；最终提交时再次检查冲突。
- 文件已存在但损坏、缺失或大小不符，不当作缓存命中；校验失败不能留下正式文件。
- 用户文件夹不可写时明确失败，不静默将私人缓存存至其他账号目录。
- 第一版不自动淘汰完整的媒体磁盘缓存；内存缓存受预算限制。磁盘清理策略另行确认，避免误删用户视频。

### 系统下载目录和环境变化

每个新普通文件任务创建时重新解析路径，而非安装/编译时写死：

1. 若明确设置应用环境变量 `BAKA_DOWNLOAD_DIR`，使用其绝对路径（允许展开环境变量及 `~`）。
2. 否则使用 `QStandardPaths::writableLocation(QStandardPaths::DownloadLocation)`。
3. Windows 遵循系统 Known Folder 下载目录重定向；Linux 遵循 XDG 用户目录/环境配置；macOS 使用系统目录。
4. 解析为空、路径无效、无写权限或空间不足时报告失败，不偷偷回落到工作目录。

`BAKA_DOWNLOAD_DIR` 是本次拟新增的可选应用覆盖项，并非系统自带变量。
Windows 不存在通用标准的 `DOWNLOADS` 环境变量，仅拼接 `%USERPROFILE%/Downloads` 无法正确处理系统重定向。
外部环境变量变更通常只对新启动进程可见；重启客户端后生效，不承诺热读取父进程的新环境。
已经开始/恢复中的任务保持原目标，只有新任务使用重新解析的位置。

## 4. 模块职责与接线

保持 QObject + 原生 Signal/Slot，不引入通用事件总线或复杂插件架构。

| 模块 | 职责 |
|---|---|
| `model/DownloadTask.h` | 任务数据与状态：ownerUid、sessionGeneration、fileId、路径、字节进度、分片游标、silent |
| `net/FileDownloader.*` | 唯一下载调度入口；初始化、分片请求、背压、超时、暂停、取消和回执匹配 |
| `store/DownloadWriter.*` | 专用工作线程逐片写文件、增量 hash、断点保存、最终提交；写完才允许下一片 |
| `store/MediaStore.*` | 按 UID 隔离缓存路径、磁盘命中、任务去重与媒体就绪通知 |
| `ui/AttachmentWidget.*` | 附件封面、尺寸标签、预览、下载/重试入口；从 MessageRow 拆出附件显示职责 |
| `ui/TransferProgressPanel.*` | 主窗口右下角非模态卡片列表，订阅任务状态，点击 × 发取消/关闭信号 |
| `ui/ChatPage*` | 可见区检查、滚动节流、当前会话懒加载接线；频道页复用相同逻辑 |
| `util/DownloadPaths.*` | 用户缓存目录、系统下载目录解析、安全文件名和冲突处理 |

下载器最终对外以 `finished(taskId, localPath)` 为主，不再强制返回整个文件字节。
头像/社区图片迁移时仅允许在有明确图片体积限制的适配层读取小文件，不能把任意大文件重新读回内存。
MainWindow 创建并共享下载器、存储及进度面板；页面不直接访问 WsCore。

## 5. 分片传输与调度

状态主线：

```text
排队 → 初始化 → 下载中 → 校验/提交 → 已完成
                  ├─ 暂停 → 排队/继续
                  ├─ 断线/退出 → 已中断 → 重新认证后恢复
                  └─ 取消中 → 已取消
任意阶段发生不可恢复错误 → 失败
```

- 初始化请求串行发送，避免无 request_id 的 system 错误无法归属。
- `file_download_ready` 用 fileId 匹配，`file_chunk` 用 transferId + chunkIndex 匹配，不只依赖 FIFO。
- 校验 fileId、transferId、块号、offset、chunk_size、实际数据长度及总大小边界。
- 写入成功并记录连续断点后才递增进度，随后再请求下一块。
- 使用 64 位字节计数；空文件单独提交，不请求不存在的第 0 块。
- 服务端提供 hash 时使用 SHA-256 增量校验；无 hash 时至少校验长度与完整分片。
- 重复片、过期片及取消后的迟到回执不得重写数据、推进游标或复活任务。
- 下载优先级：用户主动下载/打开 > 当前视口媒体和必要账号图片 > 预加载。
- 调度可在分片边界让出网络，不中断正在接收/写入的一块；排队任务不抢发分片。
- 同 UID + fileId 的媒体任务复用；用户点击正在自动缓存的媒体时提升优先级并显示进度，不重复下载。
- 同一文件反复点击下载只定位已有任务；普通文件完成后再次下载可以创建新的重名副本。
- 分片超时进行有限重试，超过次数转已中断/失败，不能无限阻塞全局队列。
- 网络收发仍在 WsCore 线程，文件写入/hash/大型复制在工作线程；主线程只更新 UI。

### 取消、断线与恢复

- 排队任务取消：直接移除；初始化中取消：标记取消，收到 transferId 后补发服务端取消。
- 传输中取消：停止请求下一块，发送 `file_transfer_cancel`；忽略在途片，清理本任务临时文件。
- 明确取消只删本任务 `.part` 和断点，不删除已完成视频、图片或用户原有文件。
- 用户暂停/网络中断保留连续完整分片和断点；恢复时使用本地“已成功落盘”游标。
- 同连接暂停/继续可使用现有 pause/resume 消息，但不能假定服务器进度一定等于客户端落盘进度。
- 重连后新建 download_init 会话，再从本地完整分片边界拉取，处理旧会话已 completed/过期的情况。
- 恢复前核对 fileId、大小、hash/分片大小；不兼容则不拼接，明确重新开始。
- 恢复 hash 时从磁盘流式重建增量状态，不序列化 QCryptographicHash 内部状态。
- 进程异常退出后只信任持久化断点；超出可靠边界的尾部截断后重取。
- 切账号使旧 sessionGeneration 失效，关闭旧写入任务；迟到回执不能写到新账号目录。
- 不在本功能中顺手实现全局自动重连；连接重新建立且认证成功后，才可继续本账号任务。

## 6. 媒体懒加载与展示

- 历史页仍按现有协议分页；只登记已收到附件元数据，不扫描/下载全部远端历史。
- 在滚动、布局变化及切会话后做节流可见区检查；仅当前实际可见 ChatPage 发起自动预取。
- 隐藏的私聊页、隐藏的频道页不能持续排队预取；已发出的一块可以安全落盘。
- 缓存命中直接使用本地路径，不发下载请求；同一 fileId 在多条消息出现时共享资源。
- 图片：占位 → 本地缩略图/解码图；解码移至后台，QPixmap 在 GUI 线程创建。
- 使用 QImageReader 尺寸探测和缩放解码，限制最大像素数/解码预算，防压缩炸弹。
- 远离视口释放解码资源但保留磁盘文件；图片轻量查看器按需打开本地原图，不自动触发外部程序。
- GIF 首版显示首帧；自动播放和动画解码另做，不让所有历史 GIF 常驻运行。
- 小视频下载好后封面显示已缓存；大视频未下载时显示播放/下载提示和体积。
- 首版视频完整下载后由用户点击使用系统默认播放器打开；不自动播放、不做边下边播。
- 视频缩略图和 Qt 内嵌播放器作为后续独立任务，不为本次下载功能新增 MultimediaWidgets 依赖。
- 视频大小标在封面右下角或封面右侧信息区；普通文件大小靠右排列，避免埋在文件名中。
- 自动下载失败仅在附件显示失败与重试，不弹全局卡片；显示失败不删除已有正常缓存。

## 7. 右下角进度卡：对齐 Web

以 `frontend/src/App.vue` 的 transfer-progress-panel 和 closeTransferProgress 为交互基线：

- 非模态、不抢焦点，挂在主窗口内容层右下角；随窗口缩放与布局调整保持边距。
- 只展示当前账号的非 silent 任务；自动图片/小视频预取和头像不弹卡片。
- 多任务纵向堆叠，新任务优先排列；超出可用高度时滚动，不挤占聊天布局。
- 卡片展示方向图标、文件名、状态、已下载/总大小、百分比及细进度条。
- 下载为蓝色，完成为绿色，失败/取消为红色；完成必须在校验与落盘提交成功后出现。
- 活跃/排队时 × = 取消任务，不是隐藏仍在后台下载。
- 完成、失败、取消时 × = 立即移除卡片；不操作则保留 3 秒自动移除。
- 卡片消失只移除 UI，不删除已下载内容；失败原因同时保留在附件重试入口/提示中。
- 已中断不是完成/失败终态，不自动当成功消失；重新认证后可恢复，× 仍表示取消。
- 暂停/继续是内部能力，本次不额外堆 Web 当前卡片没有的按钮；中断任务的恢复入口设在附件上。
- 普通文件下载完成后不自动打开文件、脚本或可执行程序；视频也只能在明确点击后打开。

## 8. 分步实施顺序

每步独立停下审阅，遵守约 5 文件/200 行的小步约束；单步超量继续拆分，不一次铺完所有模块。

1. 路径与策略：安全文件名、系统下载目录解析、账号缓存目录、可配置小视频阈值。
2. 流式落盘基础：任务数据、后台 writer、分片/长度/hash 校验、完成提交。
3. 统一下载入口：改造 FileDownloader 并迁移头像/社区图片调用，先确保现有功能不回归。
4. 控制与恢复：优先级、去重、取消、超时、账号隔离、断点持久化与重建。
5. 附件 UI：拆 AttachmentWidget，接线所有聊天类型的下载按钮及大小标签。
6. 媒体缓存与懒加载：可见区触发、本地命中、缩略图预算、图片查看及视频本地打开。
7. 进度面板：Web 同款基本状态、取消/关闭、3 秒自动消失、窗口适配。
8. 本地自动化/人工验收、README 状态同步；不自动提交，不用生产环境生成测试数据。

## 9. 验收清单

- [ ] 私聊/群聊/频道的历史与实时附件均能使用同一下载链路。
- [ ] 图片、小视频只在可见/预加载范围自动下载，切会话不批量下载旧页资源。
- [ ] 重启客户端后磁盘缓存命中不重复联网；文件被手动移除后可以重新下载。
- [ ] 视频阈值边界（小于、等于、大于 20 MiB）及未知大小行为正确。
- [ ] 大视频只手动下载，最终始终留在当前 UID 的 videos 目录。
- [ ] 普通文件使用系统 Downloads/环境覆盖路径，目录重定向、中文路径与跨盘配置可用。
- [ ] 同名、路径穿越、Windows 保留名、只读目录、磁盘满和零字节文件处理正确。
- [ ] 大文件内存不随体积增长；接收缓冲、写入队列及解码缓存均有界。
- [ ] 在途分片取消、初始化中取消、超时、重复/乱序/迟到回执不会破坏文件。
- [ ] 断线、重启恢复可续传；元数据不匹配、hash 错误和半文件不能被展示为已完成。
- [ ] 切换账号及迟到工作线程回调不串目录、任务或进度卡。
- [ ] 卡片出现、不抢焦点、× 取消、终态颜色和 3 秒消失与 Web 一致。
- [ ] 头像/社区横幅/频道聊天历史等已有功能不回归。

优先用本地假传输回执和临时目录验证，不连接生产；新增测试不恢复已删除的旧社区测试。
构建使用现有固定工具链、`-j4`；长编译提前说明，不安装或下载依赖。

## 10. 实施进度（仅非界面技术部分）

已完成并通过构建（`cmake --build` 增量编译通过，Qt 6.11.1 + MinGW 13.1）：

- `util/DownloadPaths.*`：账号媒体目录（`media/{images,videos,thumbs}`）、缓存命中查找、
  系统下载目录（`BAKA_DOWNLOAD_DIR` 覆盖 → `QStandardPaths::DownloadLocation`）、
  文件名清洗（路径穿越 / Windows 非法字符与保留名 / 截断）、重名递增、`.part` 路径。
- `model/DownloadTask.h`：任务数据与状态机枚举，状态词与 Web 端进度卡一致（排队中 / 初始化 /
  下载中 / 校验中 / 已暂停 / 已中断 / 已完成 / 失败 / 已取消），带进度百分比与终态判断。
- `store/DownloadWriter.*`：独立工作线程逐片写盘 + 增量 SHA-256；续传时按分片边界截掉半片、
  对已有前缀重算 hash；`commit()` 校验总大小与 hash 后原子改名，失败不产出正式文件。
- `net/DownloadJournal.*`：`users/<UID>/transfers/<taskId>.json` 断点记录，暂停 / 断线时写入，
  完成 / 取消时删除；临时文件已消失的记录会被清理。
- `net/FileDownloader.*`（协议与调度）+ `net/FileDownloaderTasks.cpp`（入队 / 取消 / 暂停 / 恢复）：
  - 全连接串行，一次只有一个分片在途；分片超时有限重试，超过转“已中断”；
  - 静默小文件沿用 `download(fileId)` / `finished(fileId, data)`，头像与社区图片调用方无需改动；
  - 附件走 `enqueue(task)`（`targetPath` 为空时自动落到系统下载目录并递增重名），
    对外发 `taskProgress` / `taskStateChanged` / `taskFinished` / `taskFailed`；
  - 支持 `cancel` / `pause` / `resume` / `restorePending`，迟到分片、过期 transferId、
    取消后的回执都会被丢弃；`reset()` 在断线与退出登录时保留临时文件与断点。
  - 内存任务上限 32 MiB（头像 / 社区横幅这类必须拿整份字节的小图），超过则明确失败，
    提示改用落盘任务。
